# SEO report and validation checklist: gudiyastories.com

Audit and implementation of a technical SEO foundation. No redesign; the shop,
bag, checkout, Razorpay payments, inventory and admin work as before (checked
on a production build: add to bag → checkout total ₹180 + ₹60 delivery = ₹240).

No ranking or indexing outcome is guaranteed. These changes remove technical
obstacles and give search engines accurate, complete information. What Google
then does with it depends on content, links, competition and its own systems.

---

## 1. What the audit found

**Framework.** Next.js 16 (App Router), React Server Components, behind
Cloudflare on AWS EC2. Every public page is rendered on the server; book, set,
collection and help pages are prerendered as static HTML at build time and
refreshed hourly. All important content (title, price, ISBN, age, description,
FAQs, links) is in the HTML before any JavaScript runs, so crawlers don't depend
on rendering JavaScript (checked with `scripts/seo-nojs-check.py`).

**Already in good shape (kept).** Unique titles on most pages, descriptions,
canonical URLs on book/set/collection pages, an XML sitemap, robots.txt,
`Book`+`Product` schema with ISBN and offers, `FAQPage` on books and collections,
`Organization`/`WebSite`, alt text on every image, one `<h1>` per page,
HTTPS + www→apex 301 redirects, filter URLs (`/books?value=…`) canonicalised to
`/books`, private pages (`/checkout`, `/order/…`, `/receipt/…`) noindexed.

**robots.txt and Cloudflare.** robots.txt is generated by the app
(`src/app/robots.ts`) and passes through Cloudflare unchanged (Cloudflare's
managed robots.txt / "AI crawl control" content signals are **not** enabled:
the live file matches the app's output byte for byte). Googlebot and Bingbot are
allowed on all public pages; `/admin`, `/api/`, `/checkout`, `/order/`,
`/receipt/`, `/review/`, `/track` are disallowed; the sitemap is referenced.
Nothing to change. If you ever turn on Cloudflare's managed robots.txt, it
**prepends** its rules to this file; check the result at /robots.txt afterwards.

**Analytics.** No Google Analytics or Tag Manager was installed. The site has its
own cookie-free visit counter (Admin → Analytics). Cloudflare Web Analytics is
injected by Cloudflare, but the site's security policy (CSP) was **blocking** it,
so it recorded nothing and logged a console error on every page.

## 2. What changed

### Metadata, canonicals, social previews
- `src/lib/seo.ts` (new): one helper that sets title, description, canonical,
  Open Graph (title, description, url, image, type, locale, site name) and
  Twitter card for a page. Next.js replaces (does not merge) a parent's
  `openGraph`, so each page now sets the complete set.
- Every indexable page uses it: home (unchanged), books, each book, each set,
  each collection, classes and each class, for schools, resources, gallery,
  blog and each post (as `article` with published/modified times), about, help.
- Clearer titles where they were one word, e.g. "About S.V. Bharathi, author and
  illustrator", "Bulk children's books for schools, libraries and CSR",
  "Live online classes for children". Sets: "Kindness set of 3: 3 picture books,
  Ages 6–8". Help pages got descriptions that say what the page answers.
- Every description is written from facts already on the page; trimmed to
  ~155 characters so Google is less likely to cut them.
- Root layout: `max-image-preview: large`, author/publisher, theme colour,
  optional Google/Bing verification tags (env vars, see §4).
- 404 pages: title "Page not found", `noindex, follow`, links to popular pages.

### Structured data (JSON-LD)
- `Organization`/`OnlineStore` (every page): full registered address
  (as on invoices and the Terms page).
- Books: `Book` + `Product` (Google accepts this combination for books that are
  sold). ISBN and `gtin13` from the catalogue (all nine pass the ISBN-13
  checksum), `bookFormat: Paperback`, pages, age range, author/illustrator,
  publisher, language, publication date, images (de-duplicated).
- Offers (books and sets) from `src/features/catalogue/schema.ts`: price, INR,
  stock (`InStock`/`OutOfStock`, same rule as the buy button), condition,
  seller, delivery charge (from Admin → Settings), **delivery time** (dispatch
  2–3 days, delivery 3–7 days, as on the Shipping page) and **return policy**
  (7 days, damaged/wrong books, free, as on the Returns page).
- Sets: complete `Product` with URL, audience, images and the books in it.
- `BreadcrumbList` on books, sets, collections, blog posts, classes and help,
  starting at Home, matching the visible breadcrumb.
- Blog posts: author and publisher linked to the site's Person/Organization,
  publisher logo, absolute image URL.
- **Ratings:** `aggregateRating`/`review` appear only when approved, verified
  purchase reviews exist (none yet, so none are output). Nothing is invented.

### Sitemap (`src/app/sitemap.ts`)
35 canonical URLs: home, books, 9 books, 4 sets, 8 collection pages, classes
(+ published classes), for schools, resources, gallery, blog (+ posts), about,
5 help pages. `lastmod` from real edit dates (products, classes, posts);
cover and inside-page images. Excludes bag/checkout, orders, receipts,
reviews, tracking, admin, filter/sort URLs, draft classes, unpublished posts,
draft help pages.

### Content and internal links (verified data only)
- Book pages: two new rows in the details table, **Format** ("Picture book,
  paperback") and **Themes** (the book's values), from the catalogue.
- "Browse more like this": links from each book to the collection pages it is
  actually on (age pages only when the age ranges overlap).
- Value tags on a book now link to the collection page (e.g. /books/kindness)
  instead of a filter URL that canonicalises away.
- Existing per-book text (about, when to read it, FAQs) was already written
  from the back covers and catalogue; left as is.

### Performance (mobile)
- Above-the-fold book covers no longer wait for JavaScript to fade in; they
  load eagerly with `fetchPriority="high"` (per the Next.js 16 image docs).
  Below-the-fold images still lazy-load with the fade.
- Video posters converted to sized WebP (640 px, quality 78): 1.3 MB → 0.6 MB,
  no visible quality loss. Videos themselves already loaded only near view.
- Loading screen is full height, so the footer can't jump when the page streams
  in (CLS 0.20 → 0).

### Analytics
- GA4 (`src/components/site/google-analytics.tsx`): loads only when
  `NEXT_PUBLIC_GA_MEASUREMENT_ID` is set, after the page is interactive, on
  public pages only, with advertising storage and ad personalisation denied.
  The CSP allows Google's domains only when GA4 is on.
- The Privacy page switches automatically to describe Google Analytics (cookies,
  opt-out) when it's on; until then it still says "no cookies", which stays true.
- Cloudflare Web Analytics: allowed in the CSP, so it can now record real-visitor
  Core Web Vitals (Cloudflare → Analytics → Web Analytics).

### Accessibility and semantics
- Screen-reader-only `<h2>` above book grids (correct h1 → h2 → h3 outline).
- Hidden mobile buy bar is `inert` while off screen.
- `favicon.ico` (16/32/48), `apple-icon.png` (180), `manifest.webmanifest`.

## 3. Results

**Validation (production build, `scripts/seo-validate.py`):** 35 pages,
0 failures. Every page: HTTP 200, one `<h1>`, unique title and description,
self-referencing canonical, complete Open Graph and Twitter tags, valid JSON-LD,
alt text on all images. Private pages noindexed; filter/sort/UTM URLs
canonicalise to the clean URL; robots.txt correct. One warning: the blog post
title "Screen-free learning toy for kids: how Zivoo builds thinking" is 77
characters with the suffix (Google may cut it); shorten its SEO title in
Admin → Blog if you like.

**Lighthouse, mobile emulation, same machine, median of 3 runs**
(5 for the book page). Lab numbers, not field data: they show direction,
not what visitors will measure.

## 4. Manual steps (only you can do these)

1. **Google Search Console**: add the domain property `gudiyastories.com`
   (DNS TXT record in Cloudflare is easiest), then submit
   `https://gudiyastories.com/sitemap.xml`. Use URL Inspection → "Test live URL"
   on a book page to see Google's rendered HTML.
2. **Bing Webmaster Tools**: import from Search Console, or add the site and
   submit the same sitemap.
3. **Rich Results Test**: https://search.google.com/test/rich-results on a book
   page and a set page. Expect Product (with merchant listing fields),
   Breadcrumb and FAQ to be detected. FAQ rich results are now shown by Google
   only for some authoritative government and health sites, so the FAQ markup
   is unlikely to show as a rich result; it is still valid and harmless.
4. **GA4 (optional)**: create a GA4 property, copy the Measurement ID (G-…), and
   add it on GitHub → repo → Settings → Secrets and variables → Actions →
   Variables → `GA_MEASUREMENT_ID`. The next deploy turns it on and updates the
   Privacy page. Under Indian data-protection law (DPDP Act 2023) and for
   visitors from the EU/UK, consider a cookie notice before enabling.
5. **Search Console verification via meta tag (optional)**: set
   `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION` in the server's `.env`
   (only if you use the meta-tag method instead of DNS).
6. **Google Merchant Center (optional, free listings)**: the product pages
   now carry the fields Google reads for free shopping listings.
7. **Cloudflare**: keep "Managed robots.txt" off (it is). If Bot Fight Mode is
   on, Google and Bing are verified bots and are allowed through; check
   Security → Events once to confirm no Googlebot blocks.
8. **Content (owner's knowledge needed)**: Google ranks books better with more
   independent signals: reviews from real buyers (the review email after
   delivery already asks), mentions/links from schools, blogs and press, and
   Google Business Profile for the Tirupati address.

## 5. Risks and notes

- **Welcome animation (home page).** It accounts for most of the home page's
  lab LCP. It plays once per visit and is part of the design, so it was not
  changed. If you want a faster home page score, it could be shortened or shown
  only on the very first visit; that is a design decision.
- **Cloudflare's bot-check script** (`/cdn-cgi/challenge-platform`) adds
  main-thread time on every page. It's Cloudflare's, not the site's; turning off
  "JavaScript detections" in Cloudflare → Security → Bots would remove it at the
  cost of weaker bot detection.
- **Return policy in schema** says 7 days, damaged/wrong only, free. If the
  policy on /help/returns changes, update `src/features/catalogue/schema.ts`.
  Same for delivery times and the Shipping page.
- **Stock in schema** follows the inventory; a product with no stock movement
  recorded yet counts as in stock, matching the buy button.
- **GA4** sets cookies; the Privacy page updates itself, but a consent banner is
  your call (see §4.4).
- Google decides whether and when to index pages and show rich results; that
  can take days to weeks after submitting the sitemap.
